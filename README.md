# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Webpack

Структура проекта:

- src/components/ — папка с JS компонентами
- src/components/api/ — папка с базовым кодом api
- src/components/events/ — брокер событий
- src/components/model/ — слой данных
- src/components/view/ — слой отображения

Важные файлы:

- src/pages/index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/index.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

## Архитектура приложения

Код приложения разделен на слои согласно парадигме **MVP**:

- **Model** (Модель): Содержит данные и бизнес-логику приложения, не завися от UI.
- **View** (Представление): Отображает пользовательский интерфейс (UI) и передает действия пользователя.
- **Presenter** (Представитель): Выступает посредником, получает действия от View, взаимодействует с Model и обновляет View подготовленными данными.

В паттерне **MVP** вся бизнес-логика сосредоточена в Presenter'е, который выступает посредником между Model и View. View пассивна и лишь отображает данные, полученные от Presenter'а, и передает ему пользовательский ввод, сам Presenter управляет потоком данных, обновляя Model и затем отражая эти изменения во View.

За отображение интерфейсов и взаимодействие с пользователем отвечают классы представления: `Page`, `Card`, `Basket`, `Success`, `Order`, `Contacts`. Для отображения форм используется базовый дженерик класс `Form<T>`. Для отображения всех модальных окон используется базовый класс `Modal`. В качестве базового класса для работы с DOM-элементами веб-страниц используется класс `Component<T>`, предоставленный в стартовом наборе.

Модель приложения реализована классом `WebLarekState` с интерфейсом `IWebLarekState` c использованием базового класса `Model`.

## Базовый код

### Класс `Api`

Содержит базовый класс Api для выполнения HTTP-запросов к серверу. Инкапсулирует логику работы с сетевыми запросами (GET, POST, PUT, DELETE), обработку ответов и ошибок. Используется для взаимодействия с REST API.

`constructor(baseUrl: string, options: RequestInit = {})`- принимает базовый URL и глобальные опции для всех запросов (опционально).

#### Методы

- `get` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер
- `post` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.
- `handleResponse` - обрабатывает HTTP-ответ: возвращает JSON при успешном запросе или отклоняет промис с ошибкой (из тела ответа или статуса) в случае ошибки

### Класс `EventEmitter`

Брокер событий выступает как посредник, упрощая коммуникацию между независимыми частями приложения через механизм публикации-подписки. Класс используется в презентере для обработки событий и в слоях приложения для генерации.

Конструктор класса `EventEmitter` не принимает параметров и инициализирует пустую карту событий.

Основные методы, реализуемые классом, описаны интерфейсом `IEvents`:

- `on` - подписка на событие
- `off` - отписка
- `emit` - инициализация
- `trigger` - Возвращает функцию-обработчик, которую можно вызвать позже (например, в ответ на действие пользователя). При вызове возвращенной функции:

  1. Объединяет данные из context (контекст, переданный в trigger)
     и event (данные, переданные при вызове обработчика).
  2. Инициирует событие через emit с итоговым объектом данных.

Дополнительно реализованы методы `onAll` и `offAll` для подписки на все события и сброса всех подписчиков.

### Класс `Model<T>`

Базовый абстрактный класс `Model<T>` предоставляет фундаментальную функциональность для работы с моделями данных в TypeScript-приложении. Он служит для:

1. Контроль изменений через единую точку обновления
2. Автоматическое уведомление подписчиков

`constructor(data: Partial<T>, protected events: IEvents)` - принимает частичные данные модели и экземпляр системы событий.

#### Методы

- `emitChanges`: используется для уведомления подписчиков об изменениях в модели.

### Класс `Component`

Содержит в себе методы для работы с DOM-элементами. Класс наследуют все классы представления.

`protected constructor(protected readonly container: HTMLElement)` - принимает корневой DOM-элемент для рендеринга компонента.

#### Методы

- `toggleClass` - удаляет/добавляет класс DOM-элементу
- `setText` - устанавливает текстовое содержимое
- `setDisabled` - включает/отключает кнопку
- `setHidden` - скрывает DOM-элемент
- `setVisible` - показывает DOM-элемент
- `setImage` - устанавливает элементу image значения атрибута src и alt
- `render` - отрисовывает DOM-элемент

### Класс `Form`

Содержит методы для работы с формами. Наследуется от класса Component и реализует общую логику для всех форм:

- Валидация формы
- Отображение ошибок
- Отправка данных

`constructor(protected container: HTMLFormElement, protected events: IEvents)` - принимает HTML-элемент формы и экземпляр системы событий.

#### Свойства класса

- `_submit` - кнопка для отправки формы
- `_errors` - контейнер для отображения ошибок

#### Методы

- `onInputChange` - инициализирует событие ввода
- `set valid` - включает/выключает кнопку submit'а формы
- `set errors` - устанавливает текст ошибок
- `render` - отрисовывает DOM-элемент формы

#### Обработчики событий

- `input` - отслеживает изменения в полях ввода. Для каждого изменения генерирует событие `formName.inputName:change`
- `submit` - перехватывает стандартное поведение отправки формы и генерирует событие `formName:submit`

### Класс `Modal`

Реализует модальное окно. Устанавливает слушатели на клик в оверлей и кнопку-крестик для закрытия попапа.

`constructor(container: HTMLElement, protected events: IEvents)` - принимает HTML-элемент модального окна и экземпляр системы событий.

#### Свойства класса

- `_closeButton` - кнопка закрытия модального окна
- `content` - контейнер для содержания

#### Методы

- `open` - открывает модальное окно
- `close` - закрывает модальное окно
- `render` - возвращает корневой DOM-элемент и открывает модальное окно
- `set content` - устанавливает содержимое модального окна

Конструктор принимает в себя `container`, в котором находится разметка содержимого модального окна и экземпляр класса `EventEmitter` для возможности инициации событий.

Примечание: В реализации класса `WebLarekState` отсутствует явный конструктор, поэтому он использует конструктор родительского класса `Model`, который требует данные и события.

## Слой представления

### Класс `Basket`

Представляет компонент корзины с товарами. Наследуется от базового класса `Component`. Реализует функционал для отображения списка товара и общей суммы заказа.

`constructor(container: HTMLElement, protected events: EventEmitter)` - принимает контейнер корзины и экземпляр системы событий.

#### Свойства класса

- `_basketList` - контейнер для списка товаров
- `_button` - кнопка оформления заказа
- `_total` - элемент для отображения общей суммы

#### Сеттеры

- `items` - устанавливает список товара в корзине. Если товаров нет (пустой массив), показывается надпись "Корзина пуста". Текст берется из настроек приложения `settings.basket.empty`
- `total` - устанавливает общую сумму заказа

#### Обработчики событий

При клике на кнопку оформления заказа генерируется событие `order:open`. Событие открытия модального окна с первой формой оформления заказа.

### Класс `Card`

Класс `Card` является компонентом для отображения карточки товара в различных местах приложения. Наследуется от базового класса `Component`.

`constructor(container: HTMLElement, actions?: ICardActions)` - принимает HTML-элемент карточки и опциональные действия для обработки событий.

Есть 3 варианта отображения:

1. На главной странице
2. В корзине
3. В модальном окне просмотра карточки

#### Свойства класса

Все свойства являются DOM элементами

- `_title` - заголовок карточки
- `_image` - изображение товара (опционально)
- `_description` - описание (опционально)
- `_category` - категория (опционально)
- `_button` - кнопка покупки/удаления из корзины (опционально)
- `_price` - цена
- `_itemIndex` - номер в списке внутри корзины (опционально)

#### Сеттеры

Сеттер устанавливает:

- `id` - data-атрибут идентификатора карточки
- `title` - текст заголовка карточки
- `image` - изображение товара и alt-текст с текстом заголовка
- `category` - категорию товара и соответствующие ей css-свойства
- `price` - цену товара с форматированием. Если цена равна 0, то выводится сообщение "Бесценно". Текст берется из настроек приложения `settings.messages.card.noPrice`
- `index` - порядковый номер товара в корзине

#### Методы

- `changeButton` - обновляет состояние кнопки "Купить" и ее текст в зависимости от цена и наличия этого товара в корзине. Тексты берутся из настроек `settings.buyButtonValues`

#### Обработчики событий

Если при создании карточки был передан обработчик `actions.onClick`, то добавляется:

1. На кнопку, если она есть в контейнере
2. Если нет, на сам контейнер карточки

### Класс `Contacts`

Класс `Contacts` наследуется от базового класса `Form` и реализует специфичную логику для второго шага оформления заказа - ввода email и номера телефона.

`constructor(container: HTMLFormElement, events: IEvents)` - принимает HTML-форму и экземпляр системы событий.

#### Свойства класса

Отсутствуют.

Для доступа к полям формы используется `elements.namedItem()`.

#### Сеттеры

- `phone` - устанавливает значение поля **phone** с номером телефона
- `email` - устанавливает значение поля **email**

### Класс `Order`

Класс `Order` наследуется от базового класса `Form` и реализует специфичную логику для первого шага оформления заказа - выбора способа оплаты и ввода адреса доставки.

#### Свойства класса

- `_buttonCard` - кнопка выбора оплаты онлайн
- `_buttonCash` - кнопка выбора оплаты наличными

Для доступа к полям формы используется `elements.namedItem()`.

#### Сеттеры

- `payment` - устанавливает выбор способа оплаты
- `address` - устанавливает значение поля ввода адреса

#### Обработчики событий и слушатели

При клике на кнопку оплаты "Онлайн":

1. Активирует визуальное состояние кнопки
2. Отключает состояние у кнопки "При получении"
3. Генерирует событие изменения поля `payment`

Клик на кнопку оплаты "При получении":

1. Активирует визуальное состояние кнопки
2. Отключает состояние у кнопки "Онлайн"
3. Генерирует событие изменения поля `payment`

### Класс `Page`

Класс `Page` представляет компонент для управления основным содержимым главной страницы приложения. Наследуется от базового класса `Component`.

`constructor(container: HTMLElement, protected events: IEvents)` - принимает контейнер страницы и экземпляр системы событий.

#### Свойства класса

- `_counter` - элемент для отображения количества товара в корзине
- `_catalog` - контейнер для элементов товара
- `_wrapper` - используется для блокировки прокрутки страницы при открытии модального окна
- `_basket` - иконка корзины

#### Сеттеры

- `counter` - устанавливает значение счетчика товаров в корзине
- `catalogContainer` - устанавливает содержимое каталога
- `locked` - блокирует/разблокирует прокрутку страницы

#### Слушатели событий

При клике на кнопку(иконку) корзины инициализируется событие `basket:open`. Открывается модальное окно с содержимым корзины.

### Класс `Success`

Класс `Success` наследуется от базового класса `Component`. Реализует компонент отображения успешного завершения заказа.

`constructor(container: HTMLElement, actions: ISuccessActions)` - принимает контейнер успешного заказа и действия для обработки событий.

#### Свойства класса

- `_close` - кнопка закрытия окна
- `_total` - элемент для отображения итоговой суммы

#### Сеттеры

- `total` - устанавливает итоговую сумму заказа

#### Обработчики событий

Если передан обработчик `actions.onClick`, то он вызывается при клике на кнопку.

## Презентер

Приложение использует паттерн **MVP**. Но, т.к. в приложении всего 1 страница, достаточно одного презентера. Код презентера не будет вынесен в отдельный класс, а будет размещен в основном скрипте приложения `index.ts`.

### Основные компоненты

- `WebLarekModel` - хранит состояние приложения
- `View` компоненты **Basket**, **Card**, **Contacts** и т.д. отвечают за отображение
- `EventEmitter` - брокер событий
- `WebLarekApi` - взаимодействие с сервером
- `Presenter` - бизнес-логика

### Инициализация

#### Инициализация основных компонентов

```typescript
const api = new WebLarekAPI(CDN_URL, API_URL); // api
const events = new EventEmitter(); // брокер событий
const appData = new WebLarekState({}, events); // модель данных приложения
```

#### Инициализация UI компонентов

```typescript
// Глобальные контейнеры
const page = new Page(document.body, events); // главная страница
const modal = new Modal(ensureElement<HTMLElement>('#modal-container'), events); // компонент модального окна

// Переиспользуемые части интерфейса
const order = new Order(cloneTemplate(orderFormTemplate), events); // первый шаг оформления заказа. Включает в себя способ оплаты и адрес доставки
const contacts = new Contacts(cloneTemplate(contactsFormTemplate), events); // второй шаг. Данные клиента: email и телефон.
const basket = new Basket(cloneTemplate(basketTemplate), events); // корзина
```

### События

Первоначальная загрузка каталога товаров

```typescript
api.getProducts().then((data) => {
	appData.setProducts(data);
});
```

- `products:changed` - вызывается при изменении каталога товаров
- `card:select` - устанавливает preview карточки
- `preview:changed` - открывает окно просмотра продукта
- `basket:open` - открывает модальное окно корзины
- `basket:changed` - реакция на клик "Купить" или "Удалить из корзины"
- `basket:delete` - реакция на клик на иконку удаления продукта в корзине
- `order:open` - реакция на клик "Оформить" в корзине
- `/^order\..*:change/` - реакция на клики по кнопкам "Онлайн", "При получении" и на ввод текста в поле "Адрес"
- `orderFormErrors:change` - реакция на изменение состояния валидации формы выбора оплаты и ввода адреса доставки
- `order:submit` - реакция на кнопку "Далее" в модальном окне первого шага оформления заказа
- `/^contacts\..*:change/` - реакция на ввод текста в поля "Телефон" и "Email"
- `contactsFormErrors:change` - реакция на изменение состояния валидации формы ввода номера телефона и email
- `contacts:submit` - реакция на кнопку "Оплатить" в модальном окне второго шага оформления заказа
- `modal:open` - блокировка прокрутки страницы если открыто модальное окно
- `modal:close` - разблокировка

### Используемые шаблоны
